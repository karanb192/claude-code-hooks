# OWASP LLM Top 10 2026: where these hooks land

This document maps every hook in this repo against the [OWASP Top 10 for LLM Applications, 2026 edition](https://genai.owasp.org/resource/owasp-genai-llm-top-10-2026/), published by the OWASP GenAI Security Project in August 2026 (canonical entry files live in the [official source repository](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10)). The verdicts are honest by design: a hook that intercepts tool calls at runtime cannot touch training-time or inference-cost risks, so N/A is named as N/A instead of stretched into a claim.

## The mapping

| 2026 ID | Official name | Verdict | Hook / mechanism | Why |
|---|---|---|---|---|
| LLM01:2026 | [Prompt Injection](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM01_PromptInjection.md) | Covered | [block-dangerous-commands](../hook-scripts/pre-tool-use/block-dangerous-commands.js), [protect-secrets](../hook-scripts/pre-tool-use/protect-secrets.js) (PreToolUse pattern detection) | An injected prompt cannot switch a hook off: hooks run outside the model, and the tool calls an injected agent attempts (destructive commands, secret exfiltration) are pattern-checked before they execute. |
| LLM02:2026 | [Sensitive Information Disclosure](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM02_SensitiveInformationDisclosure.md) | Covered | [protect-secrets](../hook-scripts/pre-tool-use/protect-secrets.js) (Read, Edit, Write, Bash) | Blocks reading, modifying, and exfiltrating secret files (.env, SSH keys, cloud credentials) plus secret-exposing bash: env dumps, echoing token variables, curl uploads. |
| LLM03:2026 | [Excessive Agency](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM03_ExcessiveAgency.md) | Covered | [block-dangerous-commands](../hook-scripts/pre-tool-use/block-dangerous-commands.js) (three safety levels plus ask mode), [git-safety](../hook-scripts/pre-tool-use/git-safety.js) | Caps what granted agency can actually do: destructive commands are denied outright or downgraded to a human approval prompt, tuned per safety level. |
| LLM04:2026 | [Supply Chain](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM04_SupplyChain.md) | N/A at runtime | none | Model, adapter, and training-data integrity is settled before a coding agent ever makes a tool call; see the note below for the adjacent package-install risk. |
| LLM05:2026 | [Data and Model Poisoning](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM05_DataModelPoisoning.md) | N/A | none | Poisoning happens at training and data-pipeline time; there is no tool call at the agent boundary for a hook to intercept. |
| LLM06:2026 | [Unbounded Consumption](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM06_UnboundedConsumption.md) | Partially addressable | none shipped | Rate caps and subagent caps fit the PreToolUse model, but nothing is shipped yet; a `rate-limiter` hook sits on the README ideas list and is a wanted contribution. |
| LLM07:2026 | [Misinformation](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM07_Misinformation.md) | N/A | none | Wrong-but-plausible output is not a tool call, so a hook has nothing to intercept. [session-logger](../hook-scripts/session/session-logger.js) gives after-the-fact observability of what the agent did, which is not coverage. |
| LLM08:2026 | [Hidden Context Exposure](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM08_HiddenContextExposure.md) | Partial | [protect-secrets](../hook-scripts/pre-tool-use/protect-secrets.js) | Blocks reads of operational-context files (cloud configs, infra credentials) out of the box, and its `SENSITIVE_FILES` list takes your instruction files too; a dedicated `instructions-audit` hook is a wanted contribution (note below). |
| LLM09:2026 | [Vector and Embedding Weaknesses](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM09_VectorAndEmbeddingWeaknesses.md) | Conditional | depends on your setup | Only in scope if your agent runs semantic search through a tool call a hook can see; a plain coding agent has no embedding pipeline to protect. |
| LLM10:2026 | [Improper Output Handling](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM10_ImproperOutputHandling.md) | Partially addressable | none shipped | Code the agent writes flows downstream unvalidated; a PostToolUse scanner over Write and Edit results would fit here and is a wanted contribution. |

**Note on LLM04.** For model artifacts there is nothing a runtime hook can do. The adjacent risk that does hit coding agents is agent-driven package installs (`npm install`, `pip install` run mid-session), which is the classic web risk [A06:2021 Vulnerable and Outdated Components](https://owasp.org/Top10/A06_2021-Vulnerable_and_Outdated_Components/). A `dependency-validator` PreToolUse hook that checks a package before the agent installs it is a wanted contribution.

**Note on LLM08.** This is the 2025 System Prompt Leakage entry, renamed and widened to any hidden operational context: developer instructions, retrieved policy, tool schemas ([official entry](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/final/LLM08_HiddenContextExposure.md)). protect-secrets ships patterns for secret and infrastructure files; to guard instruction files like `CLAUDE.md`, add them to its `SENSITIVE_FILES` list (the constants at the top of the hook are meant to be customized). An `instructions-audit` hook that watches instruction-file reads specifically does not exist yet and is a wanted contribution.

## What moved from 2025 to 2026

Same ten risks in both editions, nothing added or dropped; one rename and a reshuffle ([2025 list](https://genai.owasp.org/llm-top-10/), [2026 canonical files](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10)). The moves that matter for a hooks repo:

- **Excessive Agency: LLM06 up to LLM03.** The risk this repo exists for is now in the top three.
- **Unbounded Consumption: LLM10 up to LLM06.**
- **System Prompt Leakage renamed Hidden Context Exposure, LLM07 to LLM08**, widened from the system prompt to any hidden operational context.
- **Improper Output Handling: LLM05 down to LLM10.**

## Agentic risks live in a different list

The 2026 entries scope agent-specific failure modes out to the separate [OWASP Top 10 for Agentic Applications](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/), ASI01 through ASI10 ([official announcement](https://genai.owasp.org/2025/12/09/owasp-top-10-for-agentic-applications-the-benchmark-for-agentic-security-in-the-age-of-autonomous-ai/)). That list is where a tool-call hook layer does most of its work. These hooks land on four of its ten risks: **ASI02 Tool Misuse** (PreToolUse blocking is exactly the control for legitimate tools bent to destructive ends), **ASI03 Identity & Privilege Abuse** (protect-secrets guards the credential files an agent would abuse), **ASI05 Unexpected Code Execution** (block-dangerous-commands catches `curl | sh` and friends), and **ASI09 Human-Agent Trust Exploitation** (ask mode turns silent agent actions into explicit human decisions).
